AI Deepfake Detection

An image classification project connecting model training, experiment tracking, and predictions in the browser.

From a trained model to a usable app.

This AI Engineer course project predicts whether an uploaded face image is real or a deepfake. A small browser frontend sends the image to a FastAPI backend that loads a trained TensorFlow model.

The project brings together transfer learning, experiment tracking, an inference API, and Docker deployment in one workflow.

An image classifier

The documented input is a PNG or JPEG image. The API returns a predicted label and confidence for that image.

How an image becomes a prediction.

The classifier uses a frozen feature extractor and a trainable binary classification head.

  1. Upload an image

    The browser sends a PNG or JPEG file to the FastAPI prediction endpoint.

  2. Extract features

    EfficientNetB0 acts as a frozen feature extractor for the classification model.

  3. Classify the features

    Global average pooling and dropout lead into a final sigmoid layer for binary classification.

  4. Return a prediction

    The API returns the predicted real-or-deepfake label together with model confidence.

Training and inference, kept connected.

Transfer learning

The frozen EfficientNetB0 backbone supplies image features; the classification head handles the binary prediction.

Training controls

Data augmentation, early stopping, and learning-rate reduction support convergence and robustness during training.

Experiment tracking

MLflow records training artifacts. The training module regenerates dataset splits, retrains the model, and re-registers it.

Browser access

FastAPI serves the frontend and the prediction endpoint. A separate health endpoint provides a simple service check.

Model artifacts and retraining

The inference model lives at models/deepfake_detector.h5. A pretrained model is included, but the README recommends retraining before evaluation or deployment.

Running python -m src.model_training refreshes the model, training history, and MLflow artifacts so they match the current dataset and preprocessing pipeline.

API and deployment

GET /health returns a status check. POST /predict accepts a PNG or JPEG and returns the label and confidence. The server also serves the browser frontend.

The project includes CI/CD pipelines and Docker deployment. Rebuild the container after changing frontend files so the updated interface is included.

Project scope and evaluation

The README documents three availability checks for the model and dataset. These checks do not establish classification accuracy.

No benchmark accuracy or generalization result is reported in the README. Model confidence should not be read as a guarantee that an image is authentic. The documented workflow classifies images, with no video-analysis workflow described.
